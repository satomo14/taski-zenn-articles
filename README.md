# taski-zenn-articles

[Taski](https://taski-app.com/) の開発記録をZennに投稿するための専用リポジトリです。

`articles/` 配下のMarkdownを push すると、Zennの GitHub 連携により自動で公開されます（`published: true` の場合）。

## ローカルプレビュー

```
npm install
npm run preview
```

## Zenn連携

Zennアカウント: `taski_app`（表示名: とも / Taski開発者）
連携リポジトリ: このリポジトリ（`satomo14/taski-zenn-articles`）

## 運用ルール

- 投稿済みの記事は、このリポジトリからは削除しない（Zenn側は削除するとpush連携で記事も削除されるため、`published: false` に変更する運用とする）
- 下書きは `published: false` で管理する

## ⚠ 記事が公開されないとき（2026-09-01 の実例）

**まず Zenn ダッシュボード → GitHub連携 → デプロイ履歴 を見ること。**
サイト側は 404 になるだけで理由が分からないが、履歴には理由が出る。

2026-09-01、`03-ga4-zero-hits-postmortem` が9時間経っても 404 のままだった。
**デプロイ自体は「成功」しており**、お知らせにこう出ていた:

> 次の記事は投稿数の上限に達したためデプロイされませんでした:
> 03-ga4-zero-hits-postmortem
> 詳細はよくある質問ページをご確認ください: https://zenn.dev/faq#rate-limit

つまり**連携も frontmatter もリポジトリ構成も正しく、Zenn 側の投稿数上限**だった。
このときは 8/31 に2本まとめて公開した直後だった。

**対処は、上限の枠が空いてから push し直すだけ。** デプロイは push のたびに走り、
スキップされた記事も再試行される。**記事側を触る必要はない。**

このとき遠回りをした原因を残しておく:

- サイトが 404 を返すだけなので「frontmatter が悪い」「slug が悪い」「連携先が違う」と
  順に疑ってしまった。**どれも違った。**
- `zenn-cli`（`npx zenn list:articles`）はローカルで3本とも正常にパースする。
  **CLI が通ることは、公開されることを保証しない。**
- 「booksディレクトリが見つかりませんでした」という別の警告も同時に出ており、
  これを本命と誤認して `taski` 側に `books/` を作ってしまった
  （**連携先はこのリポジトリなので、向こうに作っても意味が無い**）。
  現在はこのリポジトリに `books/` を置いて解消済み。
